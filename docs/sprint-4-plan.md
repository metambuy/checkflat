## Shared design (recorded in D-027)

### Annotation format (`photo.annotation_json`, v1)
```json
{"v":1,"shapes":[
  {"t":"ellipse","cx":0.52,"cy":0.40,"rx":0.12,"ry":0.09},
  {"t":"arrow","x1":0.10,"y1":0.80,"x2":0.45,"y2":0.50},
  {"t":"freehand","pts":[[0.2,0.2],[0.21,0.23]]}
]}
```
- Numbers normalised to the image's natural width/height (0..1, finite); `rx` to the width, `ry` to the height (axis-aligned ellipse); the arrow points tail → head. Resolution-independent, so the ≤ 1600 px stored file, the thumbnails and the 800 px report copy (same aspect) map directly.
- One colour `#E60000`; stroke width `STROKE_FRACTION = 0.0075 × long side` (≈ 6 px on an 800 px report photo ≈ 0.6 mm at 80 mm; ≈ 3 CSS px on a 400 px-wide phone editor — one constant, tuned once on the P30); arrow head = a **chevron** (two stroked lines) of length `ARROW_HEAD = 4 × stroke` at 30°; round caps and joins.
- Limits: ≤ 50 shapes, ≤ 2000 points per freehand, ≤ 6000 points in total, ≥ 2 points per freehand; the column is `NULL` when there are no shapes.
- **Model + validation in the core** (`crates/checkflat-core/src/annotation.rs`: serde `Annotation { v, shapes }`, `Shape` with `#[serde(tag = "t", rename_all = "lowercase")]`, `validate()`, `parse(&str)`, `to_json()` canonical). The report crate draws from `Option<&Annotation>` and never sees JSON. **Across the API annotations are objects**, not strings: `PhotoInput.annotation: Option<Annotation>` (`#[serde(default)]`), `PhotoView.annotation: Option<Annotation>` (a stored string that fails to parse → `None` + `log::warn`, the "never break a read" policy of `row_to_observation`). The TS mirror `src/lib/annotate/model.ts` has the same types, constants and a strict `parseAnnotation(unknown)` (used by the draft parser). The constants are pinned by a report test that `include_str!`s `model.ts` and asserts the literal values (the i18n.rs pattern, stronger than the TILES comment).

### Rendering in the app: one SVG overlay component
`src/lib/annotate/ShapesOverlay.svelte` renders a shape list in `<svg viewBox="0 0 W H">` (W×H = natural size from `img.naturalWidth/Height` on load), `fit="contain" | "cover"` → `preserveAspectRatio="xMidYMid meet | slice"`, so the overlay aligns with an `object-fit: contain` (editor) or `cover` (thumbnails, unchanged) image. Stroke in image px in the editor; `vector-effect="non-scaling-stroke"` with a fixed 1.5 px stroke on thumbnails (a scaled stroke would be < 1 px at 96 px). Chosen over a canvas: no DPR handling, no redraw loop, alignment for free, and the in-progress shape is one more element. Plan §3 "Canvas overlay" → "SVG overlay".

### Editor interaction (touch and mouse)
Full-screen `AnnotationEditor.svelte` (`position: fixed; inset: 0`, rendered as a sibling of the sheet's dialog — outside its `overflow-y: auto` box), top bar Cancel / Done, bottom toolbar Ellipse / Arrow / Freehand / Undo / Delete (≥ 44 px, safe-area padding). Stage: a relatively positioned wrapper sized to the picture (img `max-width/height: 100%` in a flex item with `min-height: 0`; SVG `position: absolute; inset: 0`; `pointer-events: none` on img and SVG). Pointer Events on the **wrapper div** (`touch-action: none`, `setPointerCapture`, `e.isPrimary` only — a second finger cancels the stroke, `pointercancel` discards it, `oncontextmenu` prevented so a still finger cannot kill a stroke, `user-select: none`, `draggable="false"`). Coordinates: `(clientX − rect.left) / rect.width × W`.
- **ellipse**: drag the bounding box; **arrow**: drag tail → head; **freehand**: polyline, points thinned to ≥ 2 CSS px apart.
- A **tap** — **movement only: the pointer moved < 8 px between down and up, any duration** (the same rule as pin taps; no 300 ms limit, so a slow still press selects instead of doing nothing; `contextmenu` is prevented so a long press is not cancelled by Chrome) — in any tool **selects** the nearest shape within 16 CSS px or clears the selection — no fourth tool. Hit test: each outline sampled to a polyline (ellipse → 64 points, arrow → its segment, freehand → its points) and one point-to-polyline distance. The selected shape gets a white halo stroke underneath. **Delete** removes it; **Undo** removes the last-added shape (no redo, no undo of a delete). The tap rule lives in `editor.ts` (`end()` decides tap vs shape from the max movement; tested), not in `viewer/gestures.ts`.
- Shapes smaller than the stroke (an accidental tap in ellipse/arrow) are discarded. No move/resize, no zoom/pan in the editor (photos ≤ 1600 px shown fit-to-screen).
- Done commits; Cancel / Android Back / Escape discards. Escape is handled on the editor with `preventDefault()` **and `stopPropagation()`** (else the sheet's handler cancels the whole sheet). The description textarea is blurred before the editor opens (soft keyboard down).

### Save semantics
Annotations travel with the sheet's **Save**: a staged photo carries `annotation` in the sheet state; a stored photo's edited annotation is held in `PhotoSet.annotations` and written by `update_observation` in the same transaction. Cancel discards edits, like photos and the description. The draft (`sheet_draft`) carries both as objects validated by `parseAnnotation` (an invalid annotation drops the annotation, never the draft); fields are optional, `v` stays 1. An editor open at the moment of a kill loses its uncommitted strokes (acceptable: no camera round trip).

### Back handling
`nav.svelte.ts` gets a handler **stack** (`pushBackHandler(h): () => void`; `back()` asks the top first; `go()` clears all; `setBackHandler` is the bottom entry). The editor pushes "close = cancel" on mount and pops on destroy — no plumbing through the sheet or PlanScreen, and PlanScreen's `backStep` stays as it is.
