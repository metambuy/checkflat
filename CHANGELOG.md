- **Observation list (M7):** the project's open observations, newest first, each with its first photo (and the shapes drawn on it), ref, fraction, plan and the first line of the description; fraction chips filter it (a deleted fraction's observations stay reachable); reached from the project screen and from the plan's top bar. A tap opens that plan with the pin **selected and centred**, also while its tiles are still generating; **Back returns to the list with its filter and scroll position**, and Back again to where the list was opened. `list_observations` + `photos::first_for_project` (one query).

The draft state machine keeps `moving` through Confirm (a failed move can be retried and never turns into a new observation); the optimistic move code is gone.

## Sprint 4a — 2026-10-20 (photo annotation; D-027)
- **Photo annotation (M6):** a thumbnail on the observation sheet opens a full-screen editor — ellipse, arrow (chevron head), freehand, one colour, one stroke width; a tap selects a shape (movement only, any duration), Delete removes it, Undo the last one; Done/Cancel, Android Back and Escape. Works on staged photos before Save and on stored photos in edit mode; the shapes are saved with the sheet's Save and discarded by Cancel; the draft keeps them across a kill. Thumbnails show the shapes over the photo.
- **Format:** `photo.annotation_json` v1 — shapes with coordinates as fractions of the image (0..1), validated in the core on every write (limits: 50 shapes, 2..2000 points per freehand, 6000 per photo), `NULL` when nothing is drawn; objects across the API (`PhotoInput.annotation`, `update_observation(…, annotations)`, `PhotoView.annotation`). The photo file never changes. No migration.
- **Report:** `annotate::flatten` filled — the shapes are drawn with `tiny-skia` (antialiased, already in the tree via typst-pdf) on the **800 px report copy** after the downscale, not on the full-size image, so the report's memory peak is unchanged; a small photo without shapes is still embedded as stored.
- Dev → Seed: "with annotations" (one ellipse + one arrow per photo, a freehand on every third) for the P30 re-measure.
- **Limits kept by the editor (PR review):** a freehand stroke ends at 2000 points and at what is left of the 6000 per photo, a photo takes no more than 50 shapes, and a muted hint says so ("Drawing limit reached — undo or delete a shape", EN/PT); before, a long scribble was refused by the core on Save with the generic validation error. Done also filters the shapes through the model's rules. A stored photo's unparseable edit in a restored draft is dropped instead of becoming a clear. The sheet is `inert` while the editor is open.
- Internals: `nav.svelte.ts` back-handler stack (a modal above a screen takes Back first); `tsconfig` allows `.ts` import extensions (pure modules that import each other at runtime, as Node's test runner needs). Tests: core model + save path (create/edit/invalid/foreign id), report drawing (ring, shaft, chevron legs, freehand, antialiasing, portrait photos, `model.ts` mirror, end to end), frontend model/geometry/editor/sheet/draft (99).
- Emulator: full flow verified (draw, select, delete, save, reopen, Back, Cancel, kill/restore, report page). P30 and the re-measure: D-027.
